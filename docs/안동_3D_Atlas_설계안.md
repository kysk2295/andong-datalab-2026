# 안동 3D Atlas v1.0 설계안

작성일: 2026-09-28. 상태: 구현 전 설계. 제작자 원문과 실제 참고 사이트의 데스크톱·모바일 화면을 확인했다. 이 문서는 기존 이어드림 사업을 웹으로 설명하는 설계이며, 제출 문서나 사업의 단계 구성을 변경하지 않는다.

## 1. 결과물 정의

**서울 3D Atlas의 디자인과 지도 조작 방식을 유지하고, 안동 전역의 지형·관광지와 이어드림 사업을 탐색하는 웹사이트를 만든다.**

- 서비스명: 안동 ANDONG 3D · v1.0
- 부제: 낙동강을 따라, 안동의 낮과 밤을 잇다.
- 기본 화면: 실제 지형 위에 건물·도로·수계를 단순화한 미니어처 지도.
- 핵심 사용: 안동 탐색 → 원도심·월영교 문제 확인 → 이어드림 3단계 확인 → 조건부 예상 효과 확인.
- 이용자: 발표를 보는 심사위원·교수님, 분석 자료를 검토하는 담당자, 안동을 탐색하는 방문자.
- 제공 형태: 브라우저에서 동작하는 정적 웹사이트. 개발 완료 후 별도 배포 단계에서 공유 URL과 QR을 제공한다.

### 모바일

원본의 390×844 배치에 맞춘다. 상단 제목 아래에 환경 선택, 중앙에 지도, 아래에 간략한 장소 설명, 맨 아래에 조작부를 둔다. 탐색 패널은 하단의 ‘탐색’ 버튼으로 연다. 모바일 조작부는 원본처럼 전체·탐색·자동 비행·평면 보기·지명을 우선한다. 데스크톱의 긴 패널을 지도 위에 상시 펼치지 않는다.

## 4. 안동 공간 구성

### 두 가지 확대 수준

1. **안동 전역**: 실제 행정경계와 주변 지형 여유 범위를 포함한다. 원도심뿐 아니라 하회마을·도산서원 등 외곽 관광지를 포함한다. 전역의 건물·나무는 간소화하고, 주요 지명만 표시한다.
2. **이어드림 권역**: 원도심–월영교 구간을 확대한다. 사업 설명에 필요한 시설·버스 정류장·연결 구간을 자세히 표시한다. 안동역은 별도 교통 거점으로 연결해 볼 수 있게 한다.

카메라로 확대 수준을 바꾸며 실제 좌표와 거리 관계는 유지한다. 멀리 있는 관광지를 보기 좋게 시내 쪽으로 옮기지 않는다. 전역 지형이 넓어 도심이 작게 보이는 문제는 확대 이동과 단계별 상세 표시로 해결한다.

| 후보 | 지도에서 강조할 내용 |
|---|---|
| 안동역 | 도시 진입·귀가 교통 거점 |
| 안동구시장·찜닭골목 | 이어드림 1단계의 원도심 식음 권역 |

## 5. 탐색 패널과 동작

### 도시 탭

- 읍면동 선택 → 해당 경계 강조 → 카메라 이동.
- 번호가 붙은 랜드마크 목록 → 선택 장소 이동 → 장소 설명·좌표 갱신.
- 행정경계 표시 전환.
- 자동 비행은 검증된 랜드마크 사이를 순차 이동한다. 이용자가 지도를 조작하면 중단한다.

### 이어드림 탭

기존 사업의 세 단계 순서를 유지한다. 패널 위에는 ‘현재 자료 / 이어드림 구상’ 전환, 그 아래에 단계 목록을 둔다.

| 단계 | 현재 자료 화면 | 이어드림 구상 화면 |
|---|---|---|
| 1. 식음 → 체험 | 원도심 식음·체험 위치와 혜택 배치. 체험·문화 소비 추이는 안동시 단위로 별도 설명 | 식음 이용 후 체험 10% 할인 연결. 영수증 QR·주민증 조건형 병행은 제안 상태로 표시 |
| 2. 야간 이동 | 원도심–월영교 구간의 확인된 112번 시간표·정류장. 택시 정보는 별도 | 18:30~21:00 야간 이동 운영 구상. 운영 주체·대수·배차 간격은 미확정 |
| 3. 월영교 야간 팝업 | 조사된 주변 시설·업종·영업시간과 방문/소비건수 자료 | 팝업 검토 권역과 이용 흐름. 확정 부지·부스 수처럼 표현하지 않음 |

‘근거 보기’를 누르면 같은 패널 안에서 출처·기간·분모·조사 방법을 펼친다. 지도 위에 긴 보고서나 여러 숫자 카드를 쌓지 않는다.

사업 연결선은 **제안 흐름**으로 표시한다. 실제 도로를 확보한 경로만 도로를 따라 그린다. 미확보 구간은 점선 개념 연결선으로 표시하고 이동 시간·실제 이동량을 붙이지 않는다. 차량 애니메이션을 넣을 경우에도 실제 운행·확정 배차와 구분한다.

### 운영 시간 선택

- 이어드림 탭 안에 17:00~22:00 운영 시각 선택을 둔다. 시작값은 제안 운영창의 시작인 18:30이다.
- 확인된 영업·운행 정보만 시각 선택에 반응한다. ‘조사 기준 운영 / 조사 기준 종료 / 확인 필요’를 구분한다.
- 조사일·요일·계절 조건을 같이 표시한다. 조사일이 빠진 기존 자료는 ‘조사일 미기재’로 명시하고 실시간 영업 상태처럼 표시하지 않는다.
- 공개 방문 자료가 3시간 구간이면 해당 구간 그대로 표시한다. 분 단위 인구 흐름이나 개인 이동 궤적을 생성하지 않는다.
- 상단 ‘낮·노을·야경’은 배경 연출이다. 운영 시각과 독립적으로 작동한다. 이용자가 조명을 바꾸었다고 시설의 운영 상태가 변하지 않는다.

### 예상 효과

- 이어드림 탭의 ‘예상 효과’에서 참여율 2%·4%·10% 세 시나리오를 선택한다. 첫 버전은 검증된 세 경우를 사용하며 임의의 중간값을 보간하지 않는다.
- 기존 계산 결과의 방문당 체험·문화 소비, 연간 추가 소비, 새로 생기는 저녁 이동을 필요한 범위에서 표시한다.
- 가정·기간·단위를 함께 보여 준다. 주민증 이용 증가와 개방형 QR 참여율을 혼합하지 않는다.
- 현재 관측치와 예상치를 구분하고 ‘조건부 예상 효과’라고 표시한다. 시행 후 확정 성과처럼 쓰지 않는다.
- 계산식을 웹에서 새로 만들지 않고 기존 분석 결과 JSON의 검증된 값을 연결한다.

### 산책로 탭

원본 등산로 UI에 대응하는 보조 탐색이다. 공개 지도에 있는 안동의 보행 경로 중 검증된 경로를 수록하고, 경로·출발·도착·전체 보기·출처를 제공한다. 월영교 주변 등 후보의 연결성을 확인한 뒤 목록을 확정한다. 사업 제안 이동과 산책 경로를 섞지 않는다. 자료가 없는 코스는 만들어 넣지 않고 수록 범위를 안내한다.

## 6. 첫 화면과 발표 흐름

첫 화면은 낮·여름 모드의 안동 전역으로 시작하고 도시 탭을 연다. 과도한 자동 회전은 하지 않는다. ‘이어드림’을 선택하면 원도심–월영교가 보이도록 이동한다.

발표용 탐색은 다음 5장면을 순서대로 재생하며, 수동 다음/이전·정지를 지원한다. 도시 탭의 관광지 자동 비행과 구별해 이어드림 탭 안에서 실행한다.

1. 안동 전역: 관광지가 어디에 분포하는지 보여 준다.
2. 원도심: 식음과 체험의 위치·혜택 배치를 설명한다.
3. 원도심–월영교: 조사 시각의 시내버스 운행 공백을 설명한다.
4. 월영교: 주변 공급과 팝업 검토 권역을 보여 준다.
5. 세 단계 연결: 사업 구상과 참여율별 예상 효과를 보여 준다.

숫자는 기존 보고서 생성 스크립트가 읽는 필드와 대조해 연결한다. 오래된 문서의 숫자를 복사하지 않는다. 설문 개별 응답이나 개인정보는 웹에 싣지 않는다.

### 새로 확보·검증할 자료

| 자료 | 후보 출처 | 검증 조건 |

| 표고 | AWS Terrain Tiles / Mapzen 계열 공개 표고 | 안동 전체 수록·타일 경계·단위 확인 |
| 행정경계 | 공공 행정경계 자료 | 행정동/법정동 구분, 24개 읍면동 목록·기준일 일치 |
| 랜드마크·시설 좌표 | 안동시 관광 자료·공공 관광정보·기존 조사 | 이름·주소·좌표를 교차 확인하고 지도에서 검수 |

| 보행 경로 | 공개 지도 보행 경로 | 경로 연결·출발/도착·교량 여부 확인 |

### 웹용 데이터 구성안

- `manifest.json`: 데이터셋별 출처, 라이선스, 기준일, 건수, 단위, 좌표계.
- `boundaries.geojson`: 실제 행정경계와 행정코드.
- `places.json`: 장소 ID, 한영 명칭, 경위도, 설명, 출처, 확인 상태.
- `facilities.geojson`: 업종, 영업시간, 적용 요일, 조사일, 확인 방법, 혜택 상태.
- `routes.geojson`: 실제/제안 구분, 교통 수단, 방향, 출처, 시간표 연결 ID.
- `metrics.json`: 지표값, 공간 단위, 기간, 분모, 단위, 출처, 관측/예상 구분.
- `scenarios.json`: 기존 분석에서 추출한 세 참여율의 결과와 가정.
- 지형·건물 데이터: 구역별 전처리 파일. 건물 형상을 보존할 수 있는 구조를 선택하고 메타데이터와 레코드 수를 검증한다.

행정동 집계를 건물별 소비처럼 칠하지 않는다. 월영교 방문 비중과 소비건수 비중은 서로 다른 집계 체계임을 표시하며 구매 전환율로 바꾸지 않는다. 공개되지 않은 값은 0으로 표시하지 않는다.

## 8. 기술·성능 설계

원본의 미니어처 표현을 맞추기 위해 Three.js 중심의 정적 웹을 기본안으로 한다. 이전 대화에서 제안한 MapLibre 중심안보다 이번 사용자의 ‘동일 디자인’ 조건에 직접 맞는 선택이다.

- 지도 좌표를 지역 평면 좌표로 변환하고 지형·건물·도로·수계를 같은 기준에 놓는다.
- 공유 형상·재질과 인스턴싱을 반복 나무·건물 유형에 적용한다. 고유한 건물 윤곽은 병합·단순화 방식과 병용한다.
- 전역은 낮은 상세도, 확대 권역은 높은 상세도로 단계별 로딩한다.
- 지형 높이 강조는 원본의 4배를 초기 검토값으로 삼고 안동 수계·랜드마크를 확인해 확정한다. 적용 배율을 화면에 표시한다.
- 강·호수의 수면과 지형을 맞춘다. 안동댐 상·하류의 수면 높이를 무조건 동일하게 두지 않는다.
- 모바일은 픽셀 비율·그림자·나무 밀도·건물 상세도를 낮춘다.
- 비·눈·물결·조명은 풍경 연출이며 실시간 날씨·영업·교통을 뜻하지 않는다. 동작 줄이기를 지원한다.
- 데이터 로딩 진행, 실패·재시도, WebGL 사용 불가 안내를 제공한다.
- 구체적인 FPS나 로딩 시간은 실제 측정 후 보고한다. 성능 개선 적용만으로 수치를 주장하지 않는다.

최종 검수 항목:

- 안동 전역과 외곽 랜드마크가 들어 있고, 잘못된 서울 지명·좌표·데이터가 남아 있지 않다.
- 낙동강·안동호·임하호가 건물이나 바닥 아래에 묻히지 않고, 주요 교량이 수면 위에 놓인다.
- 기본 UI의 색·글꼴·패널·모바일 구성은 원본의 같은 상태와 비교한다. 도시 지형 차이는 정상 차이로 구분한다.
- 운영 시각과 배경 연출의 선택이 독립적으로 동작한다.
- 미확인 영업시간은 확인 필요로 남고, 특정 노선의 공백을 전체 교통수단 부재로 설명하지 않는다.
- 제안 경로·팝업·조건부 효과가 실측이나 확정 운영처럼 보이지 않는다.
- 참여율 2%·4%·10%의 값이 기존 분석 출력과 일치하고, 단위·기간·가정이 보인다.
- 정보 패널과 README에 출처·기준일·자료 한계·높이 추정 및 강조 여부가 있다.
- 브라우저에서 실제 검수한 결과와 측정한 성능만 완료 보고에 쓴다.
