# 안동 Atlas 시각·인터랙션 재설계

2026-09-29. 사용자가 taste-skill을 명시적으로 요청해 적용한다. 원래의 스킬 미사용 지시는 이번 요청으로 변경되었다. 이후 2026-09-29 사용자 요청으로 기존 기능과 독립 시안 페이지를 Railway에 배포했다. 이후 세 시안 모두 완성하라는 사용자 요청에 따라 v1.5 로컬 앱에 세 모드를 통합했다. Railway는 v1.4 유지, 새 변경은 배포 보류다.

## 디자인 판독
지도 중심 여행 앱의 전면 시각 개편. 사람·차·실제 지형을 주인공으로 하고 장소 탐색, 여행 계획, 혜택 비교를 같은 화면 구조로 연결한다. 마케팅 랜딩페이지가 아니므로 해당 스킬의 히어로·이미지 생성·스크롤 마케팅 블록은 적용 대상이 아니다. 실제 현장 이미지 요구를 유지하고 생성 이미지를 현장 사진으로 사용하지 않는다.

DESIGN_VARIANCE 6 / MOTION_INTENSITY 4 / VISUAL_DENSITY 4. 고정 지리와 입력 폼의 사용성을 위해 예측 가능한 구조를 유지하며, 패널/탭/선택 상태 전환에만 짧은 움직임을 적용한다. 기존 Vite·Three.js·일반 DOM 구조를 유지하는 자체 CSS 디자인이며 외부 디자인 시스템의 공식 구현을 표방하지 않는다.

## 변경 전 점검
- Arial·한글 시스템 글꼴, 10~12px 설명, 녹색 톤의 거의 동일한 작은 버튼과 패널 반복.
- 반투명 둥근 패널이 지도 상하좌우를 덮음. 탐색 폭310px에 범위·탭·사진·계획·입력이 겹쳐 여행 시작까지 길게 스크롤.
- 도시/이어드림/산책로/여행의 기존 탐색 구조와 URL/query는 유지할 가치가 있음.
- 키보드 조작·사진 출처·미확인 자료 표시·사업 수치·주민증/QR 구분은 보존.
- 주요 자산: 실제3D 지도, 확인된 월영교/하회마을/안동역 사진. 기존 실제사진·로드뷰·후기 기능은 이어서 완성.

## 디자인 규칙
- 고정72px 상단, 하나의 연속된 탐색 패널, 넓게 열린 지도. 별도 카드 외곽 대신 여백과 소수의 구분선을 사용.
- 글꼴: 로컬 Pretendard Variable(OFL), 본문14px, 입력14px, 작은 출처11~12px. 버전 표시는 안내에만 남김.
- 중립 회백색과 짙은 먹색, 기존 안동 지도와 이어지는 녹색 하나를 행동 강조색으로 사용. 시뮬레이션의 의미 있는 지도 색은 별도 데이터 표현.
- 모서리: 입력/버튼6px, 떠 있는 툴/대화상자12px, 고정 패널0px. 모든 표면에 유리 효과를 사용하지 않음.
- 시스템 밝기와 수동 화면 테마를 지원. 지도 날씨/야경과 UI 테마는 분리.
- 레이어: 지도0, 표식2, 고정 UI5, 툴/장소7, 재생9, 모바일패널12, 대화상자와 선택목록은 브라우저 top layer.
- 움직임: 선택된 탐색 패널 등장, 눌림 피드백, 사진/콘텐츠 변경. transform/opacity만 애니메이션. reduced-motion이면 생략.

## 구현 범위 (v1.5)
상단 탐색/화면 모드, 패널 접기, 지도 도구 간소화, 여행 입력 리듬과 시작 버튼, 지도 위 클릭 가능한 여정 미리보기, 사진 중심 장소 탐색, 사진 창과 방문 팁 재구성, 모든 드롭다운과 대화상자 색/형태/포커스 통일.


## 이전 단계: 적용 전 시안 요청 반영 (v1.4 기록)
사용자가 “바꾸기 전에 예시를 보여줘”라고 요청하여 본 앱 적용을 중지하고 `public/design-preview/`에 독립 시안만 만든다. 기존 main.js/index.html은 이 디자인 파일을 가져오지 않는다. 기존 v1.4 빌드 위의 iframe에만 디자인을 적용하므로 지도·여행·사진은 실제 기능이며, 메인 페이지는 기존 화면을 유지한다.

- A 지도 중심: 연속된 왼쪽 패널에서 설정, 하단 고정 여행 시작, 지도 공간 확보.
- B 코스 중심: 설정 패널을 접고 실제 계산된 코스의 구간을 하단에서 선택해 그 구간부터 여행.
- C 사진 중심: 출처 확인 월영교/하회마을/안동역 사진을 고르고 지도·실사진으로 이동.

시안 주소: `http://localhost:4174/design-preview/index.html`. 공개 시안: `https://andong-atlas-production.up.railway.app/design-preview/index.html`. 사용자 선택 전 본 앱에는 시각 개편을 적용하지 않는다. 최종 접근성·성능·모바일 완성 검수는 선택된 방향을 본 앱에 통합하는 단계에서 진행한다. 스킬의 랜딩페이지 전용 체크를 제품 앱에 무리하게 적용하지 않는다.

시안 확인: 인앱 브라우저 1280×720에서 A/B/C 전환, A의 하단 고정 여행 시작, B의 식당 구간 선택→실제 여행 시작, C의 하회마을 선택→실제 사진 대화상자 연결을 확인했다. 기존 본 화면은 재디자인 파일을 가져오지 않는다.


## 세 모드 통합 완료 (v1.5 · 로컬)

상단의 지도 탐색/코스 여행/사진 탐색은 URL `layout`과 연결된다. 페이지를 복제하지 않고 같은 지도·여행 설정·실사진 기능을 공유한다. 별도 시안 페이지의 A/B/C 버튼과 내부 모드도 양방향으로 동기화한다. 여행 재생 중 다른 모드로 바꾸면 재생을 종료하고 그 모드로 돌아간다.

- A: 사진 탐색 헤더를 접고 전체 장소 목록·생활 풍경 바로 가기를 연속된 왼쪽 패널에 배치.
- B: 설정을 접고 코스 전체가 들어오도록 지도 구도를 맞춘다. 하단에 시간·구간·수정·시작을 두며 입력이 유효하지 않으면 구간 시작도 막는다.
- C: 실사진, 출처·권리자·라이선스, 장소 이동을 먼저 보여준다. 미수록·로딩·실패 상태를 처리한다.
- 모바일390×844: 두 줄 상단, 접이식 패널, 수평 코스 목록. 사업안 비교 표에는 가로 스크롤 안내와 고정 항목 열을 사용한다.
- 테마: 사용자의 시스템 밝기를 따르되 수동 전환 가능. 모바일 패널의 기존 색 변수 충돌을 해결했다. 날씨와 별도로 동작한다.
- 조작: 키보드 포커스, 검색 드롭다운, Escape/바깥 클릭, 동작 줄이기를 유지했다. 최상위 계절 목록을 선택할 때 풍경 패널이 먼저 닫히던 이벤트 충돌을 해결했다.

출처 확인 사진만 사용했고 생성 사진을 만들지 않았다. 관광지 사진은 레퍼런스의 그래픽을 장식용으로 복제하는 대신 실제 장소를 탐색하는 콘텐츠로 사용한다. 실제 검수 화면은 `artifacts/v1.5/`, 기능 검수는 `QA.md`에 기록한다.
