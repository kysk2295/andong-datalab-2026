# 이어드림 1인칭 체험 게임 · 2026-09-29

## v1.23 — 장소별 체험 진입

`relay-entry.js`는 장소에서 관련 체험으로 향하는 URL/문구를 공유한다. 명소 목록과 선택 카드, 탐색 사진, 사진 정보, 여행 장소, 관광지 내부, 혜택/단계 지도, 사업안 거점이 같은 매핑을 사용한다. 대시보드에는 전체 릴레이 시작/이어서 하기와 네 개의 바로가기, 지도 조작 바에는 상시 시작 링크가 있다.

`relay-visit.js`는 market/meal/workshop/transit/bridge/popup 진입 기록을 본 여정과 분리한다. 단독 공방만 쿠폰 없이 작업할 수 있고, 이전 식사나 혜택 완료 상태를 만들지 않는다. 이후 단계는 실제 체험 완료 조건을 따른다. 외부에서 저장된 visit 값을 본 여정 복원에 신뢰하지 않는다. `at`는 클릭한 장소로 한 번 진입한 후 URL에서 소비하며, 새로고침은 저장 진행 상태를 복원한다. 기존 팝업 저장 키를 유지한다.

`play=1`은 전체 릴레이의 현재 상태를 유지한 채 바로 체험 화면을 연다. 새 여행의 시작은 원도심 골목이다. 기본 지도 첫 화면을 유지한다. 단독 방문은 전용 기록을 표시하고 전체 릴레이 완주로 표시하지 않는다.


## v1.22.0 — 월영 밤마당 공간 확장과 직접 체험

사용자 문서의 F&B·전시·공연·이벤트·수변 기획과 외부 공간 디자인 시안 세 곳을 참고했다. 부산항 1부두 행사 조감도는 긴 테이블·전구선·천 장식, Beijing Night Market은 컨테이너 키친과 공연 분리, MIXC YARD 이미지는 목조 파빌리온·골목·테라스 구성의 참고다. 원본 작품 이미지는 배포하지 않고 새 3D 형상으로 구현했다. 출처는 앱의 사진·현장 정보와 `artifacts/relay/v16/references/SOURCES.md`에 있다.

- 보행 영역 62×44m, 9개 부스, 6개 구역과 15개 목적지. 먹거리 마당·공예 골목·달빛 무대·강변 찻자리·놀이 마당·수변 전망대가 충돌을 피하는 공통 경로로 이어진다. 건축물·테이블·무대·안내도가 `relay-popup-layout.js`의 배치를 공유한다.
- 음식 조리대/도구/진열, 몽골텐트와 목조 매대, 공용 좌석, 전구·무대 조명, 3인 공연, 관람객/산책 방문객, 강변 난간과 다리 야경을 배치했다. 정적 관람객은 geometry를 재질별로 합쳐 인스턴싱한다.
- 간고등어·사과·식혜 구매 시연을 추가했다. 구매한 음식·차 맛보기 손동작, 3D 엽서 위 세 종류 도장 직접 찍기/버튼 대체 조작/PNG 저장, 현재 3D 화면 사진 저장, 별도 야외 탈 전시를 제공한다. 투호와 장단 체험은 확장한 구역에서 이용한다.
- 상시 화면은 현재 구역과 기본 메뉴만 유지한다. 지도 버튼을 눌러 실제 장면 배치와 현재 위치를 확인하고 목적지까지 걸을 수 있다. 기존 전체 지도/혜택업체/릴레이 경로도 이어진다.
- 맛보기·도장·사진 기록은 유효값만 복원하며, 기존 식사·인증·체험 상태와 팝업 단독 방문 저장을 분리한다. 취소/미구매/다른 단계에서는 완료가 기록되지 않는다. 공연을 마쳐도 무대 앞 위치에 머무른다.

운영 중인 현장이나 실측 복원이 아닌 제안 공간이다. 부스 상호·가격은 시연값이고 구매는 실제 거래가 아니다. 사람과 음식은 여전히 게임용 3D 모형이며 사진과 동일한 실사를 주장하지 않는다.


## 직접 조작과 릴레이 안내 · v1.13

`relay-meal.js`는 raycast로 식품 조각을 집고 카메라 앞 젓가락 위치에 붙입니다. 화면의 입 안내 안에 놓아야 한 입이 기록됩니다. 잘못 놓기·pointercancel·blur는 원래 접시로 돌려보내며 체험 취소는 음식과 카메라를 복원합니다. 세 입 후 별도 확인으로 EAT를 저장합니다.

`relay-workshop.js`는 꽃·양조 재료·표찰에 목적지 판정을 적용합니다. 잘못된 순서/위치에는 진행하지 않고 복원합니다. 주전자/다관의 실제 주둥이 좌표와 받는 용기 사이에 물줄기를 배치하고, 종료 시 변환을 복원합니다. 마우스 대체 조작도 재료 선택과 정량 확인을 거칩니다. 탈 색칠 도움은 실제 텍스처에 구역별 붓질을 추가합니다.

`relay-tuho.js`는 화면 입력을 항아리 입구 높이의 평면에 투영합니다. 표시된 도착점으로 포물선 연출을 재생하고 두 수평축의 오차로 성공을 판정합니다. 결과 전에 취소하면 기회를 소비하지 않습니다. 축약한 게임 규칙이며 강체 물리 시뮬레이션은 아닙니다.

`RelayScene`은 목적지 바닥 표식/방향 안내와 Pointer Lock 조작 모드를 제공합니다. 미지원 환경은 드래그 조작으로 이어갑니다. `relayCarry`는 실제 저장 상태에서 식사→영수증→쿠폰→사용한 프로그램/금액을 읽으므로 프로그램을 바꾸거나 장면을 미리 봐도 혜택이 늘지 않습니다.



## 사진 대조와 연결 보행 · v1.12

`relay-architecture.js`는 시장 상가, 곡면 지붕, 정자, 숲 지형을 생성합니다. 반복 바닥재·난간·볼트·수목은 InstancedMesh로 묶습니다. 지붕 경계에서 Float32 반올림으로 음수의 분수 거듭제곱이 발생하는 오류를 수정했고 유한 좌표/법선을 검사합니다.

`relay-journey.js`의 네 연결 정의와 충돌 배치를 `relay-journey-set.js`가 3D 공간으로 구성합니다. `relay-ui.js`는 현재 완료 상태를 유지한 채 연결을 시작하며 마지막 지점에 도착해야 GO를 저장합니다. 안내를 중단하면 그 위치에 멈추고 같은 구간을 재개합니다. 이전 장면 복귀/새로고침은 마지막 저장 단계로 돌아가며 쿠폰·완성품은 유지합니다. 연결 구간은 일시 상태로 저장하지 않습니다.

수동 보행과 안내 보행은 기존 공통 충돌/A* 로직을 사용합니다. 식사→영수증은 같은 실내의 카메라 방향/위치를 보존합니다. 이동은 실제 거리와 시간을 줄인 제안 동선이며 로딩 경계가 존재합니다. 현장과의 완전 일치 또는 실사 품질을 주장하지 않습니다.

## 공간·상호작용 보강 · v1.11

`relay-details.js`는 기존 장면에 실제 이용 위치(입구·식탁·계산대·마당·작업대·난간·부스)를 구성합니다. `relay-navigation.js`는 충돌 검증 및 A* 경로를 제공하며, 직접 걷기와 안내 이동이 같은 장애물을 사용합니다. 안내 이동은 화면 버튼 또는 Escape로 중단할 수 있습니다.

`relay-scan.js`는 샘플 영수증과 별도 카메라/렌더 타깃으로 휴대폰 화면을 표시합니다. 영수증을 드래그하거나 방향 버튼으로 옮겨 일정 시간 정렬해야 발급 단계로 갑니다. 실제 카메라 권한, 외부 QR 판독 또는 인증 API는 사용하지 않습니다.

`relay-materials.js`와 `public/assets/relay/materials/`는 CC0 PBR 맵과 HDR 환경광을 사용합니다. 재질은 장소의 원본 사진이 아니며, 현장 자료와 구분합니다. 그림자·기존 낮/밤 조명을 유지하고 GPU 자원은 장면 해제/스캔 종료 시 정리합니다.

기존 `/` 진입점과 지도는 변경하지 않았습니다. 공개 배포는 하지 않았습니다.

사진 8장 원본을 저장했다. 이번에 안동역과 하회별신굿탈놀이 사진을 추가 확보했다. 한국관광공사 식당 사진 3건은 연결 시간 초과로 원문 링크와 실패 상태를 보존한다. 공예문화전시관 공식 페이지의 휴관·체험 예시 금액·주차 안내, 개목나루 문보트/황포돛배 체험시간·게시 영업시간을 확인했다. 게시 시간은 당일 운항·예약 가능 여부를 보장하지 않는다.

체험 금액은 기획 시연 예시다. 현장 업체의 실내 도면, 확정 제휴, 원도심 거점의 실제 운영 시간·정원·예약 가능일은 확보하지 못했다. 월영교·식당·작업대·팝업은 입체 재구성이며 실사 또는 측량 복원이라고 표시하지 않는다.

추가 파일: `relay-task-model.js`(입력 규칙), `relay-workshop.js`(3D 도구 조작), `relay-checkout.js`(주문·결제 시연), `tests/relay-task.test.mjs`. 별도 런타임 의존성을 설치하지 않고 기존 Three.js를 사용했다.


첨부 기획의 핵심은 관광객 한 명이 식사·영수증 혜택·전통 체험·저녁 이동·월영교와 팝업을 실제로 이용하는 흐름이다. 기존 지도 첫 화면을 유지하고 `?experience=relay`에서 직접 체험에 진입한다. 사업의 3단계와 관광객의 다섯 연결 지점(식사·혜택·체험·이동·월영교와 팝업)을 구분한다. 체험 중 진행 표시와 다음 단계의 연결 이유를 보여준다. 공개 배포는 수행하지 않았다.

## 조사 자료와 사진

- `public/data/relay-research.json`: 14곳의 공식·공개 자료, 확인일, 근거별 상태, 장면 연결, 미확인 항목.
- `public/data/relay-media.json`: 사진 출처·저작자·라이선스·촬영일·원본 SHA-256·다운로드 상태.
- `public/media/relay/`: 월영교, 하회마을, 하회탈, 찜닭, 국화차, 안동소주 술병의 원본 JPEG 8장. 음식/다기 참고 사진을 특정 시연 식당·현재 체험장의 현장 사진으로 표시하지 않는다.
- 한국관광공사 식당 사진 서버 연결 시간 초과, 식당 사진 서버 지연으로 수집하지 못한 3개 항목은 원문 링크와 미수집 상태로 남겼다. 표시된 사진은 임의 생성하거나 잘라 쓰지 않았다.
- `scripts/prepare-relay-research.py`: 출처별 조사 결과와 설명 경로 재생성.
- `scripts/collect-relay-media.py --only jjimdak tea soju`: 지정 자료 수집, 이미 저장된 원본은 보존. 사진 실패를 성공으로 취급하지 않는다.

공예문화전시관/소주박물관의 안내를 원도심 제안 거점의 확정 운영 정보로 전용하지 않는다. 국화차와 월영야행의 과거 행사는 현재 상시 운영의 근거가 아니다. 2026 탈춤축제 일정이 월영교 팝업의 입지·운영 허가를 증명하지 않는다. 112번 기점 출발 시각은 월영교 정류장 승차 시각이 아니다.

## 구현 경계

1. 공개 자료를 참고한 게임용 공간이며 실제 식당·골목·작업장의 정밀 실내 복원/실사 VR이 아니다. 지형을 잇는 실측 보행 시뮬레이터나 정식 버스 운행 모델도 아니다.
2. 영수증 인증, 체험 10% 할인, 주문·결제, 원도심 체험 예약, 야간 연결차량·팝업은 사업 시연이다. 실제 개인정보·카메라·결제 정보를 수집하지 않는다.
3. 실제 가격·현재 대기·회차 정원·현장 접수·주차 요금·문보트/분수 최신 운영을 확인하지 못한 항목은 명시했다. 제안 요금/시간과 공식 확인 자료를 분리한다.
4. 전통주 공정과 꽃·물 양 맞추기는 직접 조작하는 교육용 활동이다. 물리 기반 액체/식품 시뮬레이션이 아니다. NPC는 정해진 안내 대사를 제공한다.
5. 색칠은 UV 텍스처이며 다운로드는 색칠 기록 평면 이미지다. 사진 촬영본·실제 공예품 배송 기능이 아니다.
6. 브라우저 로컬 저장만 사용한다. 실제 사용자 계정·다중 기기 동기화·성과 분석에 합산하지 않는다.
7. 장면별 GPU 자원은 최대 5개만 유지하고 교체 시 해제한다. 참고 사진은 정보 패널에서만 지연 로드한다.
