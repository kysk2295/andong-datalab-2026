# 안동 3D Atlas v1.2

**현재 v1.2는 로컬 검수판입니다. 사용자의 배포 보류 지시에 따라 Railway에는 반영하지 않았습니다.**

서울 3D Atlas의 화면 구성을 참고해 만든 안동 전역 지도와 이어드림 탐색 웹사이트입니다. 지도·분석 데이터는 로컬에 저장되어 있으며, 실행 중 외부 지도 API나 개인 API 키를 사용하지 않습니다.

## 실행

Node.js 20.19 이상에서:

```sh
npm install
npm run dev -- --port 4173 --strictPort
```

브라우저에서 http://localhost:4173/ 을 엽니다. `index.html`을 파일로 직접 열면 모듈과 데이터가 로드되지 않습니다.

```sh
npm test
npm run build
npm run preview -- --port 4174 --strictPort
```

`dist/`가 정적 배포 결과입니다. Railway 공개 주소: https://andong-atlas-production.up.railway.app . 배포 서버가 `.json.gz`에 `Content-Encoding: gzip`을 붙이는 경우와 붙이지 않는 경우를 모두 처리합니다. DecompressionStream을 지원하지 않는 브라우저에서는 원본 JSON을 읽습니다.

## 구현 기능

- 안동 24개 읍면동 실제 경계 선택·강조, 전역/장소 확대, 회전·이동·확대·축소·북쪽 정렬.
- 공개 지도에서 확인한 장소와 팀 분석 기준점 11곳. 출입 지점 좌표인 하회마을·병산서원은 ‘입구’로 구분.
- 낮·노을·야경·비·눈, 독립적인 사계절 나무, 평면 보기·지명·자동 비행·전체 화면.
- 이어드림 3단계, 현재 자료/제안 전환, 조사 기준 시간표·영업 종료, 조건부 예상 효과.
- 월영교 현장 조사 18곳의 종료 정보, 그중 주소 자료와 일치하는 17곳의 좌표 표시·이동.
- 기존 분석 JSON과 일치하는 참여율 2%·4%·10% 시나리오. 공개 보행 구간 탐색, 출발·도착 표시.
- 모바일 탐색 패널, 키보드 조작, 동작 줄이기 설정, 자료 로딩 실패 안내·재시도.

타일 경계로 나뉜 지오메트리가 포함되므로 위 수록량은 실제 강·도로·건물의 고유 개수와 같지 않습니다. 지도 스냅샷은 2026-09-13입니다. 다운로드 시각과 정확한 원천 주소는 `public/data/manifest.json`에 있습니다. 원본 응답 캐시는 `.cache/`에 있으며 버전 관리에서 제외했습니다.

지형과 건물 높이는 4배로 강조했습니다. 내륙 표고 자료에서 발견된 음수 이상치 3점은 주변 5×5 격자의 유효 표고 중앙값으로 보정하고 `terrain.json`의 `correctedSamples`에 원본·대체값을 보존했습니다. 전역 수계는 표고 격자에 윤곽을 입혔고, 상세 수계는 7개로 병합한 다각형의 수면을 평탄하게 표현했습니다. 수계 안 DEM의 하위 25% 높이를 바탕으로 렌더링 지형만 평탄화하며 `district.terrain` 원본 표고는 그대로 유지합니다. 수리학적 수면 모형은 아닙니다.

기존 타일의 6,486 Polygon에 GlobalBuildingAtlas 연구 데이터의 비중복 건물 윤곽 54,640개를 보충했습니다. 이는 안동 행정경계 안의 고유 건물 수나 전수 조사 결과가 아닙니다. 지형 표시 bbox는 인접 지역 일부를 포함하며, 연구 데이터의 분할·인식 오류와 지도 누락이 남아 있습니다. 원천의 위성 추정 높이를 사용하고, 기존 건물의 높이가 없으면 6m를 적용합니다. 지붕 테두리·옥상 설비·창문·나무·가로시설 형태는 미니어처 표현이며 건축 외관이나 수목 현장 조사 결과가 아닙니다.

GBA의 동아시아 타일을 스트리밍해 표시 범위 55,223개를 추출했고 모두 높이 정보와 연결했습니다. 기존 건물과 면적/중심점 기준으로 겹치는 583개를 제외해 54,640개를 보충했습니다. 상세 범위에 해당하는 1,253개도 `district.json`에 연결했습니다. OSM과 GBA의 경계 차이 때문에 완전한 중복 제거를 보장하지 않습니다.

## 분석 자료 규칙

`analysis.json`은 기존 `보고서/교수브리핑_20260922/수치.json`과 `보고서/성과도출_20260922/시뮬레이션결과.json`에서 필요한 집계만 추출합니다. 시설 위치는 `안동_상권_음식점_20260630.csv`와 현장 조사 명칭을 일치시켰습니다. 개인정보·설문 개별 응답을 포함하지 않습니다.

- 방문당 체험·문화 소비는 안동시 단위. 건물별 소비로 표시하지 않습니다.
- 월영교 방문/소비건수 점유율은 2022.4~6 자료의 별개 집계이며 전환율이 아닙니다.
- 영업 종료만 조사된 시설은 종료 전이라도 ‘개점 미확인’으로 표시합니다.
- 버스는 2026.09 수집 시간표. 실제 실시간 도착·운행 정보가 아닙니다.
- 현재 화면의 점선은 권역 간 위치 관계, 구상 화면의 점선은 사업 제안입니다. 실제 도로 주행 경로가 아닙니다.
- 예상 효과는 기존 모의실험 중앙값이며, P5~P95는 모형 가정에 따른 범위입니다.
- 산책로는 공개 지도상의 개별 보행 구간입니다. 공식 추천 코스나 연속된 완주 코스를 뜻하지 않습니다.

## 재수집

```sh
npm run data
```

저장소의 기존 분석 원본 파일이 필요합니다. 행정경계·표고·OpenFreeMap 타일을 캐시하고 전처리합니다. API 키는 필요 없습니다. `prepare-facilities.py`는 공개 상가 좌표와 조사 목록을 연결합니다. `npm run build`와 `npm run dev`는 지도 JSON을 gzip으로 압축합니다. `map` 19.08→4.34MB, `buildings` 19.91→2.52MB, `district` 1.36→0.23MB. `npm run data`는 전역 기본 자료/분석만 재생성하며, 상세·GBA는 아래 별도 순서를 사용합니다.

## 사업 모형과 상세 기대효과 (2026-09-28 확장)

이어드림 → 기본안/확대안을 누르면 원도심 인증·체험 건물과 월영교 팝업 모형, 보행자, 도로망을 따라 이동하는 버스가 나타납니다. 모형 또는 거점 버튼으로 확대하며 ‘버스 따라가기’로 차량을 가까이 볼 수 있습니다. 18:30~21:00 밖에서는 이용자·차량이 표시되지 않습니다. 장면 일시정지 및 동작 줄이기를 지원합니다.

- 기본안 20곳 / 확대안 83곳, 팝업 8개·연간 12개월은 최신 시뮬레이션의 계산 가정입니다. 확정 시설 수·운행 대수가 아닙니다.
- 20개 효과 항목과 P5/P50/P95, 회복 목표, 주민증 조건형 혜택, 안별 비교를 제공합니다. 별도 참여율 2/4/10% 시나리오도 상세 패널과 연결됩니다.
- 주민증 증가분은 원도심 식음 이용 회귀 추정 × 참여 규모로 계산합니다. QR 인증 건수를 주민증 이용에 합산하지 않습니다.
- 팝업 기준점 128.758095, 36.576700는 월영교 서측 주차장 권역(OSM 76992439)의 **시각화용 제안 위치**입니다. 토지 이용·부지 협의·실제 설치 가능성을 검증한 부지가 아닙니다. OSM 주차장 경계 안에서 건물 윤곽·수계를 피하는 약25.2×18m 표시 범위로 축소했습니다. 원본 DEM 5×5 표본의 높이 차가 약0.9m인 지점으로 조정했습니다. 경사면에서 모형 일부가 묻히지 않도록 수평 받침을 표시하며 이는 시공·토목 계획이 아닙니다.
- 차량 경로는 상세 OSM 도로망의 78개 좌표를 연결한 양방향 시각화입니다. 일방통행·통행 제한·실제 BIS 노선은 반영하지 않으므로 운행 계획으로 사용할 수 없습니다. 사람 수·차량 수·속도·건물 크기는 설명용 연출입니다.
- `scripts/prepare-solution.py`로 최신 원본 수치와 도로 경로를 재생성합니다. 원본 계산 파일이나 제출본을 수정하지 않습니다.

## Railway 배포

Dockerfile은 웹 앱만 빌드하고 Node 정적 서버가 Railway의 PORT에 응답합니다. 데이터 재수집이나 상위 분석 원본은 배포에 필요하지 않습니다. .cache·node_modules·원본 보고서는 업로드하지 않습니다.

프로젝트 `83cb6cfa-06b7-418d-9cf9-b11d0bbe424e`, 서비스 `andong-atlas`. 저장소 루트에서 `railway up andong-atlas --path-as-root --service andong-atlas --detach`로 수동 배포합니다. 이 디렉터리의 Railway 연결을 확인한 후 실행하세요.

## 원도심–월영교 상세 보기 (v1.2)

- 전역 / 도심 전체 / 원도심 상세 / 월영교 상세. 첫 화면은 도심 전체이며, 상세 bbox는 128.716,36.555,128.774,36.586입니다.
- 상세 건물 2,022개와 835개 도로·보행 구간, 창문·창틀·옥상 테두리·일반 설비·그림자를 표현합니다. 도로 폭·차선 수 미기재 시 추정합니다.
- 상세 숲은 식생 영역에 배치한 나무 최대 18,000개(모바일 7,000개), 다면체 수관·가지·계절색으로 표시합니다. 제안 모형 주변, 건물, 도로는 수관 너비까지 고려해 비워 둡니다.
- 차량 최대 720대/보행자 1,400명(모바일 최대 280대/480명)은 관측량이 아닌 연출 수량입니다. 도로 길이와 원도심 중심 거리로 분산하고, 같은 구간의 중복 시작 위치는 제외합니다. 같은 방향 앞차와 간격을 유지하며 보행자는 건물 윤곽을 피한 보도·공원 길에서 왕복합니다. 상세 배경 차량은 연결된 OSM 도로와 일방통행 태그를 따르며 막힌 단방향 끝에서는 멈춥니다. 교통신호·회전 제한·교차로 충돌·실시간 교통량은 모델링하지 않습니다. 사업 제안 버스는 별도의 왕복 설명 경로입니다.
- 건물 외벽과 지붕에 안정적인 색 구분을 적용했습니다. 실제 색상 태그가 없는 건물 색은 연출입니다. 외벽 하단은 경사면까지 연결하고 도로·보도 면은 실제 지형 격자의 삼각형에 맞춰 분할해 경사 변화에서 끊기거나 지형을 뚫지 않도록 했습니다.
- 공원·잔디·운동장 46개 원본 경계를 적용했습니다. 내부 보행로가 없는 공원의 길과 수목·벤치·화단은 경계 안에 만든 미니어처 연출이며 실제 조경 배치도가 아닙니다. 원본 수목13개 위치와 추가 장식 수목을 구분해 저장합니다. 공원·가로수 모두 계절 설정에 반응합니다.
- `사람·차량 가까이`, `웅부공원 산책`으로 개체와 바닥 접점을 확대해 볼 수 있습니다.
- 차량 차체·창·바퀴·전조등, 사람 팔다리 보행, 원본 위치의 횡단보도·정류장과 일반 가로시설을 표시합니다. 시설의 실제 형태·모든 보도의 존재를 보장하지 않습니다.
- 수면·소형 선박·탑승객·월영교 난간과 정자를 표현합니다. 교량 구간의 도로·보행자는 수면이 아니라 별도 교량 높이를 따릅니다. 교량 높이는 양안 표고에서 정한 표현값이며 구조 실측값이 아닙니다. 카메라가 언덕 속으로 들어가지 않도록 시야선을 검사합니다.
- 기본안/확대안의 모형과 원본 기대효과·주민증 조건형 추정값을 연결합니다. 부지·부스 수·버스 수는 확정 운영계획이 아닙니다.
- 전역 건물은 한 번에 메시로 조립해 수만 개 임시 지오메트리를 만들던 비용을 줄였습니다. 데이터는 실행 시 외부 API 호출 없이 로컬 정적 파일에서 읽습니다.

재생성 순서 (Python 의존성은 uv의 임시 환경):
```sh
mkdir -p .cache/detail
curl --fail 'https://api.openstreetmap.org/api/0.6/map?bbox=128.716,36.555,128.774,36.586' -o .cache/detail/osm.xml
python3 scripts/prepare-district.py
node scripts/prepare-district-terrain.mjs
uv run --with requests --with ijson python scripts/import-gba.py
uv run --with shapely python scripts/merge-buildings.py
python3 scripts/prepare-street-assets.py
python3 scripts/prepare-solution.py
uv run --with shapely python scripts/prepare-water.py
uv run --with shapely python scripts/prepare-parks.py
npm test
npm run build
```
GBA 첫 추출은 동아시아 윤곽 타일 약 1.56GB와 높이 자료 약 362MB를 스트리밍하므로 네트워크 시간이 필요합니다. 전체 타일 대신 안동 표시 범위 추출본만 `.cache/detail/gba-andong.json`에 저장합니다. `.cache`는 배포·버전 관리에서 제외합니다. 재수집 시 데이터 개수 변화와 스냅샷 테스트 기대값을 검토해야 합니다.
